# Видео личных рекордов

Записываются три опубликованные canvas-игры: Pit Lane Flight, Cowboy GP и Pit Stack.
Сапёр пока является административным прототипом и не подключён к видеозаписи.
Гостевые игры и административный тестовый режим не записываются.

Используется текущее S3-хранилище изображений (`USE_S3=True` и уже настроенные AWS_*).
Новый бакет, публичный список видео, доступ к камере/микрофону и CORS для прямой
загрузки не требуются: фрагменты проходят через Django в S3 multipart upload.
Объекты `media/arcade-videos/...` публичны при публичной политике существующего
бакета. Пользователь уведомлён об этом перед игрой. Для записи нужны поддержка
MediaRecorder/captureStream и доступное временное хранилище IndexedDB.

Сохраняются игровое поле и счёт; для тетриса также следующая фигура и canvas-эффекты.
Это не захват всего окна браузера и не запись игрового звука. Разрешение до 480 px
по ширине, 12 fps, целевой битрейт 240 кбит/с. Разрешение самой игры не уменьшается.
Ресурсы устройств различаются: полную запись нельзя гарантировать при закрытии
вкладки во время игры, нехватке места, сбое кодировщика или неподдерживаемом браузере.
Сбой видео не лишает игрока результата и не заменяет старую запись обрезанным файлом.

Фрагменты временно пишутся в IndexedDB. После завершения сервер проверяет владельца,
принятый результат, отсутствие исключения/ручного добавления и текущий личный рекорд.
Файл передаётся по 5 MiB без сборки целого видео на диске приложения. Поддерживаются
MP4/WebM, полная запись до 1 GiB / 5 часов. Превышение лимита считается ошибкой,
а не успешной усечённой записью. Замена старой записи происходит после полного
получения и проверки размера; удаление старого объекта — после коммита БД.
У одного игрока сохраняется одно видео на каждую игру. Равный рекорд не заменяет видео.

Незавершённую загрузку можно повторить кнопкой. При следующем посещении той же игры
в течение суток загрузка уже завершённой записи автоматически продолжается,
если она по-прежнему является рекордом. При изменении рекорда незавершённая загрузка
старого результата больше не принимается.

В админке: **Видео рекордов аркад**; также плеер внутри соответствующей попытки.
Старые и ручные попытки не имеют видео задним числом. После ручной корректировки
рекорда оставшееся видео относится к указанной в нём исходной попытке, а не к
сгенерированной записи нового результата. Видео поступает с клиента и не является
самостоятельным доказательством честности или заменой серверной проверки игры.

Для удаления брошенных multipart-загрузок старше суток и повторения неудачного
удаления старых объектов при начале новой рекордной загрузки выполняется ограниченная
автоматическая очистка. Для гарантированной очистки также в дни без новых рекордов
рекомендуется ежедневная задача:

```sh
python manage.py cleanup_arcade_videos
```

Она не удаляет действующие видео рекордов. S3-ключу требуются PutObject,
AbortMultipartUpload, GetObject/HeadObject и DeleteObject в существующем media-префиксе.
Не следует применять правило удаления всех объектов `arcade-videos/` по возрасту:
актуальное видео рекорда может храниться долго.
