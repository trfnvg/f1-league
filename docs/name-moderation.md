# Локальная модерация имён и логинов

Проверка выполняется на сервере при регистрации (имя и @логин), при смене
@логина в настройках и при валидации нового значения `UserProfile.handle`.
Ошибки показываются у соответствующего поля; некорректная форма ничего не
сохраняет, включая изменение почты. Пароли и почта через словарь не проходят.

## Проверка имени и логина во время ввода

Регистрация и настройки аккаунта проверяют логин через 400 мс после ввода.
На регистрации так же проверяется имя: формат и словарь, но не занятость.
Одинаковые имена разрешены. `clean_display_name` используется и живой
проверкой, и формой регистрации; нормализуются только пробелы. На странице
настроек имени пока нет — там живая проверка применяется только к логину.
Показываются формат, занятость и результат той же модерации `clean_handle`,
что применяется при сохранении. Незавершённые запросы отменяются, устаревшие
ответы игнорируются. Пустое поле не проверяется; при сбое сети или ограничении
частоты можно отправить форму и получить обычную серверную проверку.

`POST /account/handle/check/` защищён CSRF, ответы запрещено кэшировать.
Логин не передаётся в URL. Ответ содержит только доступность, код и сообщение,
без почты, имени или идентификатора владельца. Доступность публичного логина
сама по себе публична. Для вошедшего пользователя свой неизменённый логин
доступен. Проверка ничего не резервирует и не создаёт аккаунт: при отправке
формы занятость проверяется повторно, уникальность защищена ограничением БД.

Отдельные общие для воркеров DB-лимиты: 60 проверок в минуту и 600 в час
на IP (IPv6 /64). Используется существующая настройка доверенных прокси
`AUTH_TRUSTED_PROXIES`. Код 429 содержит `Retry-After`; браузер выдерживает
паузу. Лимиты проверки логина не блокируют регистрацию, вход или восстановление.
Новых сервисов, переменных окружения и миграций не требуется.

Проверка имени: `POST /account/name/check/` с полем `name`. Ответ содержит
`valid`, `code`, `message`, не ищет аккаунты по имени и ничего не сохраняет.
Те же CSRF/no-store и отдельные лимиты 60/минуту и 600/час на IP. Ошибка,
пауза или запоздалый ответ одного поля не затрагивают другое поле. Для имени
показывается «Имя соответствует правилам», а не «Имя свободно».

## Данные и лицензия

Готовые русская и английская базы LDNOOBW / Shutterstock находятся в
`league/data/name_moderation`. Они закреплены за коммитом
`5faf2ba42d7b1c0977169ec3611df25a3c08eb13`. Источник, авторство, дата
импорта и полная CC BY 4.0 сохранены в `NOTICE.md` и файле лицензии.
Исходные словари не изменяются; исключения и дополнения отделены в
`policy.json`. В интернете ничего не запрашивается при регистрации.

Это список нежелательных слов, а не юридический реестр и не полный
перечень политиков. `policy_identities` — отдельный ограниченный набор
имён/псевдонимов политиков и явных нацистских отсылок по правилам Fastlap.
Он не определяет политические взгляды пользователя и не является
автоматическим определением экстремизма. Новые варианты нужно добавлять
явно, вместе с тестами; фильтр не гарантирует обнаружение всех обходов.

## Как устроена проверка

`name_moderation.py` сравнивает ограниченный набор проверочных вариантов:
Unicode-нормализация, удаление невидимых знаков, регистр, транслитерация,
похожие кириллические/латинские символы, распространённые замены цифрами
и растягивание одной буквы. Отображаемая строка этим не переписывается.

Слова экранируются `re.escape`, регулярки компилируются один раз на процесс.
Произвольные регулярки из внешней базы не исполняются. Вход ограничен
150 символами, логины дополнительно ограничены существующими 3–30
латинскими буквами и цифрами. Проверка не требует API, GPU или новой БД.

Большая часть слов сопоставляется целиком, по словам или с цифровыми
суффиксами, чтобы не блокировать обычные имена по случайным подстрокам.
Для явно обсценных составных ников есть ограниченный список сильных корней.
Неоднозначные короткие корни проверяются только в начале/после отдельных
приставок: например, `EstebanOcon31` не должен блокироваться из-за `eban`.
Предусмотрены исключения для обычных слов исходной базы и имён, в том числе
Семён/Semen, Dick, Lolita и Тит. Числа 88 и 1488 сами по себе не запрещены.

На локальной машине разработчика после прогрева: медиана чистой проверки
0,017 мс, p95 0,041 мс на 2000 примерах. Это не измерение всего HTTP-запроса
и не гарантия времени ответа сервера Timeweb.

## Существующие пользователи

Нет миграции, массового переименования, удаления или блокировки аккаунтов.
Проверка не вызывается при аутентификации. Старый неизменённый @логин
не мешает сменить почту; реальное новое значение проходит модерацию.
Старые отображаемые имена автоматически не перепроверяются.

## Изменение правил

1. Добавить/исключить слово в соответствующем списке `policy.json`.
2. Добавить запрещённый пример и похожий допустимый в `test_name_moderation.py`.
3. Запустить тесты, проверить ложные срабатывания, затем деплоить.
4. Перезапустить процессы приложения: правила кэшируются в памяти.

Для обновления сторонней базы нужно выбрать конкретный upstream-коммит,
сверить изменения, обновить атрибуцию/лицензию при необходимости и тесты.
Не заменять списки автоматически на каждом старте сайта.
