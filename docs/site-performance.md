# Оптимизация страниц — 28 октября 2026

Первая итерация сокращает лишнюю работу сервера без изменения дизайна,
качества изображений, правил очков и дедлайнов. База и файлы игроков не меняются;
миграции и новые сервисы не нужны.

## Что изменено

- Главная повторно использует уже загруженный календарь в общей таблице.
- Выбранный сезон читается один раз на HTTP-запрос, а не отдельно во view
  и в контексте шаблона. Между запросами кэш не сохраняется.
- Общая таблица не загружает объекты пользователя и этапа заново для каждой
  строки Score: потребители используют их ID и численные результаты.
- Live Paddock читает подиумы только последнего опубликованного этапа.
  Предыдущие очки по-прежнему учитываются при определении личного рекорда.
  Исторические тексты Crazy Prediction и остальные поля прогноза не загружаются.
- При обновлении радио не собирается контекст всей страницы с навигацией,
  аватаром и настройками аркад. HTML фрагмента остаётся таким же; ответ no-store.
- Рейтинг соревнования аркады выбирает лучшую попытку каждого игрока в БД
  через ROW_NUMBER, вместо передачи всех попыток и verification JSON в Python.
  Порядок равных результатов, счётчики начатых попыток, ограничения по дедлайну,
  исключение администраторов и правила для неактивных пользователей сохранены.
- В перенесённой Fastlap Main исходные прогнозы нужны только для локальных
  решений по Crazy Prediction и Driver of the Day. Без таких решений таблица
  использует сохранённые очки, не загружая тексты всего сезона. При наличии
  решений выбираются только соответствующие прогнозы; проверка хеша текста,
  границ участия и срока сохранения остаётся на месте.
- Изображения результатов ниже на главной загружаются лениво и декодируются
  асинхронно. Сами изображения, их размеры и сжатие не изменены.

Подход соответствует рекомендациям Django: сначала измерять, затем уменьшать
объём выборки и ненужную обработку. См. [оптимизация БД](https://docs.djangoproject.com/en/6.0/topics/db/optimization/)
и [оконные выражения](https://docs.djangoproject.com/en/6.0/ref/models/expressions/#window-functions).

## Синтетические замеры

`tests/profile_site.py` всегда создаёт изолированную SQLite в памяти, независимо
от DATABASE_URL окружения. Настоящая база не открывается. Набор: 250 игроков,
24 этапа, 6000 прогнозов/результатов очков и 10 000 попыток Cowboy GP.
Медиана пяти повторов после прогрева; время включает Python и локальную БД.
Исходный код до оптимизации взят из Git HEAD 86fdfab, данные одинаковые.

| Операция | До, мс | После, мс | SQL до → после |
| --- | ---: | ---: | ---: |
| Расчёт общего рейтинга | 75,6 | 22,8 | 5 → 5 |
| Формирование пяти новостей | 37,9 | 4,9 | 6 → 6 |
| Рейтинг соревнования, 10 000 попыток | 88,4 | 9,5 | 2 → 2 |
| Главная гостя | 117,2 | 31,4 | 17 → 15 |
| Обновление Live Paddock | 114,9 | 28,5 | 16 → 13 |
| Расчёт таблицы Fastlap Main без локальных решений | 63,7 | 28,9 | 7 → 6 |
| Главная участника Fastlap Main | 193,8 | 67,3 | 30 → 27 |
| Страница общего рейтинга | 214,2 | 169,9 | 12 → 11 |
| Страница таблицы Fastlap Main | 99,4 | 62,2 | 22 → 21 |

Важен не только счётчик SQL: загрузка прогнозов в новостях сократилась
с 6000 до 250 объектов, на главной участника — с 12 001 до 251.
В аркаде БД возвращает 250 строк рекордов вместо 10 000 полных попыток.

Это не замеры Timeweb, не браузерное время полной загрузки и не тест
одновременной нагрузки. Они не означают, что весь сайт в интернете будет
открываться в столько же раз быстрее. Сеть, фотографии, сервер и число
одновременных запросов нужно измерять отдельно.

## Проверка

```sh
python tests/profile_site.py
python manage.py test league.test_site_performance --noinput
```

Новые тесты проверяют границы выборок, отсутствие повторного чтения сезона,
равенство HTML радио, личные рекорды при ещё не опубликованном следующем ГП,
локальные решения лиги, старый хеш Crazy Prediction, оба вида аркад,
равные очки, позднее завершение, незавершённые попытки и границу дедлайна.
В тестах нет нестабильных требований к миллисекундам.

Полный серверный набор: 421 тест на PostgreSQL 16 — успешно.
Новые 11 тестов отдельно проверены и на SQLite.
Браузерная проверка WebKit: 38 настоящих страниц на ширине 390 и 1440 px,
включая формы, таблицы, радио, приглашения и управление лигой — успешно.
