# Мои лиги: первый интерфейс

В навигации авторизованного игрока появился пункт **Мои лиги** (`/leagues/`).
Создание: название, будущий открытый этап, «Классика» или «Паддок».
Ближайшая уже заведённая карточка с будущим дедлайном выбрана по умолчанию.
Не нужно ждать открытия приёма прогнозов за 7 дней: состояние `soon` не
мешает созданию лиги. Отдельная строка настроек сезона создаётся при успешном
POST, если администратор пока добавил только карточку этапа. Прошедший дедлайн
и явно закрытый администратором этап по-прежнему недоступны.
Один базовый прогноз используется во всех зачётах, очки считаются отдельно.
В «Паддоке» крейзи засчитывает владелец/модератор этой лиги после дедлайна.
Роль модератора назначает только владелец; это не `is_staff` платформы.

## Приглашения и ограничения

- Ссылка действует 7 дней, может быть отозвана; максимум 5 действующих ссылок
  на сезон лиги. В БД сохраняется SHA-256, исходная ссылка показывается при
  создании один раз. Прокси/access-логи с URL приглашения нужно защищать от
  публичного доступа и настроить маскирование токенов перед массовым запуском.
- Открытие ссылки не зачисляет игрока: после входа требуется POST-подтверждение
  с CSRF. Повторное подтверждение не дублирует участие. При позднем вступлении
  первый зачётный этап выбирает сервер из будущих открытых.
- По умолчанию: 10 активных собственных лиг, 3 создания за 10 минут, 250
  участников в лиге. `PRIVATE_LEAGUE_MAX_OWNED`/`PRIVATE_LEAGUE_MAX_MEMBERS`
  можно переопределить в настройках Django. Это прикладные квоты, не замена
  общему rate limiting на регистрацию, вход и запросы.
- UUID не даёт доступа: все страницы и действия проверяют активное членство.
  Чужой staff не видит закрытую лигу. Изменения только POST + CSRF,
  HTML экранируется; приватные ответы `no-store`, страницы `noindex`.
- Списки лиг и участников с пагинацией; таблица без горизонтальной прокрутки.
  Создание, вступление, отзыв приглашения и смена роли записываются в аудит.

## Совместимость

Миграции `0041`/`0042` только добавляют таблицы. История старой компании не
не пересчитывается, прежние страницы и очки сохраняются. Миграция `0043`
регистрирует эту компанию как **Fastlap Main** и связывает её исторических
участников с разделом «Мои лиги». Владелец — существующий владелец явного
импорта либо подтверждённый админ исходной установки `trfnvg`; другой staff
автоматически владельцем не назначается. На чистой установке без этого
аккаунта/истории миграция ничего не создаёт. Повторное применение не дублирует
членство. Миграция не меняет прогнозы, очки, дуэли, колесо или staff-права.

Fastlap Main закреплена первой в списке её участников. Её новая страница
читает прежние `Score` и `SeasonScore`, поэтому все местные поправки и
сезонные бонусы сохранены; страницы этапов ведут на действующий интерфейс.
Это мост чтения истории, не перенос её в новый объективный расчёт. Для legacy
лиги новый пересчёт запрещён до сверенного переноса. Старые дуэли/колесо не
становятся многолиговыми автоматически; выдача новых локальных бонусов —
следующий отдельный этап. Глобальные проекции рассчитываются, но отдельный
публичный интерфейс общего зачёта ещё предстоит сделать.

После публикации официального результата рассчитываются новые лиги; при
сбое callback модератор может повторить локальный пересчёт. Старый апдейт
подиума, изменивший базовый прогноз, блокирует новую проекцию такого этапа,
вместо попытки угадать исходные ответы. Подробности: `competition-scoring.md`.

## Проверка

```sh
DATABASE_URL=sqlite:///:memory: python manage.py test league.test_leagues league.test_competition_scoring league.test_private_league_ui
PYTHON_BIN=/path/to/python PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/private_leagues_browser.mjs
```

Проверки HTTP включают чужие UUID/сезоны/роли, CSRF, границы дедлайна,
идемпотентное вступление, отзыв/срок ссылки, квоты, локальную модерацию и
автоматическую публикацию. Chromium проверяет 7 реальных Django-страниц на
ширинах 320/390/768/1101/1440 без миграции пользовательской БД. Это не тест
на физическом iPhone. Конкурентные блокировки PostgreSQL, нагрузка Timeweb,
регистрация/почта/MFA и восстановление резервных копий остаются отдельными
обязательными проверками перед массовым запуском.

### Доработка Fastlap Main

221 Django-тест прошёл: добавлены проверки первой будущей карточки после
дедлайна, старта до открытия прогнозов, отсутствующих настроек календаря,
идемпотентной регистрации компании, сохранности исходных данных и точного
чтения очков с дуэльными/сезонными бонусами. Чужие пользователи в Main не
зачисляются без исторического участия; доступ по одному UUID не открывается.
