# Очистка репозитория — 28.10.2026

## Что проверено

Проверены URL bindings, вызовы Python, includes/render шаблонов, literal static
references, CSS URL, dataset игровых canvas и генераторы графики/звука.
Отсутствие буквального имени файла само по себе не считалось доказательством
ненужности: динамические изображения и загружаемые пользователями трофеи
исключены из автоматического удаления.

## Что удалено из текущей версии

- 30 заменённых графических/звуковых файлов, 27,77 MiB: старые варианты фонов,
  героев, колёс, ракеты, кабинета сапёра и прежний саундтрек Pit Stack.
  Актуальные версии сохранены, их байты не менялись.
- Старая программа генерации саундтрека `tools/compose_pit_stack.mjs`.
  Рабочий генератор `compose_pit_stack_v2.mjs` сохранён.
- `leaderboard-chart.js`: график уже отсутствует на страницах результатов.
- Три неиспользуемых шаблона: `arcade.html`, `arcade_control.html`,
  `arcade_competition_history.html`.
- 13 неиспользуемых обработчиков/вспомогательных функций в `views.py`, старый
  helper `arcade_library.history` и неиспользуемые импорты. Активные URL
  по-прежнему ведут в `arcade_library`. Админ-превью сапёра теперь рисуется
  напрямую, без диспетчеризации через старые реализации остальных игр.
- Всего из `views.py` убрано около 450 строк; правила игр/начисления не менялись.

9 файлов из `media/` и 2 `.DS_Store` **исключены из Git**, но оставлены на диске:
это локальные данные, их нельзя считать ненужными только по поиску по коду.
Загрузки из production/S3, рабочая БД и пользовательские аккаунты не удалялись.
В сумме текущий отслеживаемый набор облегчён примерно на 38,8 MiB плюс текст.
Это не равнозначно уменьшению размера старой Git-истории или первой загрузки игры.

Исторические описания создания артов в `docs/` сохранены. Упомянутые там
прежние версии изображений можно восстановить из истории; это не текущие
зависимости игры. Историю графики эта операция не вычищает.

## Отдельно: удаление базы из истории

Пользователь отдельно согласовал удаление `db.sqlite3` из всей истории и
принудительное обновление GitHub. Это не сброс паролей и не удаление рабочей БД.

Перед такой операцией нужна закрытая копия Git вне проекта и сохранение всех
текущих изменений. Переписывается только путь `db.sqlite3`, без массового
удаления других файлов истории. SHA старых коммитов меняются. Публикация
должна использовать lease с проверенным прежним SHA удалённой ветки.

Проверки завершения: нет пути `db.sqlite3` в `git log --all` и достижимых
объектах; дерево main совпадает с протестированным; удалённая ветка указывает
на переписанный SHA. Локальная рабочая база остаётся игнорируемым файлом.

Чужие клоны/форки, старые URL коммитов, кеши GitHub и скрытые PR refs этим
не гарантированно очищаются. Для них нужен отдельный контроль/обращение в
GitHub Support. Другие старые рабочие копии нельзя сливать обратно в очищенную
историю. Пароли затронутых аккаунтов при совпадении с рабочими сменить отдельно.
